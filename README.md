# vovo-plugin

vovoscan content sources, described by **JSON rule manifests**: no code, only requests to the declared hosts and
extractions (JSONPath, CSS selectors) followed by known transformations.
**The mobile app interprets them and makes the requests itself** (`vovoscan-mob`, `core/sources`): their content
never goes through our servers. The backend validates the contract (`vovoscan check-source`).

This repository is also a **plugin repository**: its `repo.json` index lets the app list and install its sources.
A source reaches a user in one of two ways:

- **Official**: an admin installs and activates the manifest on the vovoscan server (rights basis required); the
  server distributes it to every user.
- **Third-party (user plugin)**: a user adds it in the app from a repository (`repo.json`), a link to a manifest,
  or a `.vovo` file. It is private to that user (synced to their own devices only). A key that is already an
  official source on the server cannot be added again ("Already available as an official source.").

## Contents

```
repo.json                      repository index (generated by scripts/build-index.py, committed)
schema/source.schema.json      v1 contract (copy from vovoscan-be: src/vovoscan/features/catalog/domain/contract/)
sources/<key>/source.json      one manifest per source
sources/<key>/README.md        rights, settings, activation
sources/<key>/CHANGELOG.md     one "## <version>" section per release, newest first
sources/<key>/icon.png         optional icon (PNG, ≤ 256 KB)
scripts/build-index.py         writes repo.json (--check: fails if it is out of date)
scripts/pack.py                builds dist/<key>-<version>.vovo packages
scripts/check-versions.py      semver versions, bumped when a manifest changed
scripts/check.sh               runs every check, then validates the manifests with the backend contract
```

The scripts need only Python 3 (standard library); `scripts/check.sh` also needs the backend (`uv`).

## Check

```bash
scripts/check.sh          # sibling backend (../backend or ../vovoscan-be), or VOVOSCAN_BE=<path>
```

It runs, in order: `check-versions.py` (see [Versioning and updates](#versioning-and-updates)),
`build-index.py --check`, the schema comparison with the backend, and `vovoscan check-source` on every manifest.

## Writing a source

Full brief for plugin authors (engine behaviour, limits, feature requests): [`docs/AUTHORING.md`](docs/AUTHORING.md).

- `key`: `^[a-z0-9][a-z0-9-]{1,62}$`, equal to the directory name (`sources/<key>/`); `vovoscan` is reserved.
- `kinds`: `comic`, `book` (served today), `audiobook`, `video` (planned by the contract). Each declared kind has
  its rules in `content` (`comic`: a list of pages; `book`: an EPUB file).
- Sections: `catalog` (paginated list, search via `{{search}}`), `title` (details + units: a list, or `single` for
  a book in a single file), `content`.
- Values: a JSONPath (`"$.title"`), or `{ "path" | "css" | "const" | "template", "attr", "all", "then": [...],
  "default" }`. Transformations: `trim`, `collapseSpaces`, `string`, `number`, `integer`, `lower`, `absUrl`,
  `first`, `notNull`, `regex`, `replace`, `join`, `map`, `pluck`, `format`.
- Templates: `{{settings.<setting>}}`, `{{page}}`, `{{search}}`, `{{lang}}`, `{{id}}` (title), `{{unitId}}` (unit).
- Hosts: the app only contacts those in `hosts` and in `url`-type settings, with a separate HTTP client that never
  sends the vovoscan session.
- **Rights**: `rights.basis` is `public-domain` or `licensed`, and `rights.notes` states the source's terms.
  For an official source, the backend refuses activation without a rights basis confirmed by an admin (proof
  required for `licensed`). No source that bypasses a protection (CAPTCHA, anti-bot) or violates a site's terms.
- The manifest must stay ≤ 256 KB.
- The schema changes in the backend first, then is copied here (`scripts/check.sh` checks that they are equal).
  The Gutenberg manifest has a copy in the backend tests (`tests/fixtures/sources/gutenberg.json`).

## Repository format (repo.json)

`repo.json` (formatVersion 1) sits at the repository root and is **generated**: never edit it by hand, run
`python3 scripts/build-index.py` and commit the result. The output is deterministic (sources sorted by key,
2-space indentation, trailing newline).

```json
{
  "formatVersion": 1,
  "id": "app.vovoscan.official",
  "name": "vovoscan official sources",
  "homepage": "https://github.com/djabiridrissou/vovo-plugin",
  "sources": [
    {
      "key": "gutenberg",
      "name": "Project Gutenberg",
      "version": "1.0.0",
      "contractVersion": 1,
      "kinds": ["book"],
      "langs": ["en", "fr"],
      "rights": "public-domain",
      "manifest": "sources/gutenberg/source.json",
      "sha256": "<lowercase hex sha256 of the manifest file bytes>",
      "icon": "sources/gutenberg/icon.png",
      "changes": "What changed in this version."
    }
  ]
}
```

- `id`: reverse-DNS (`^[a-z0-9]+(\.[a-z0-9-]+)+$`), stable; it identifies the repository for a user.
- Each entry copies `key`, `name`, `version`, `contractVersion`, `kinds`, `langs` from the manifest, and
  `rights` = `rights.basis`, so the app can show the list without fetching every manifest.
- `manifest`, `icon`: relative to the URL of `repo.json` (absolute `https://` URLs are also accepted by the app).
  `icon` is present only when `sources/<key>/icon.png` exists (≤ 256 KB).
- `sha256`: of the exact bytes of `sources/<key>/source.json`. On install and update the app fetches the manifest,
  checks the hash, and checks that `key`, `version` and `contractVersion` match the entry; otherwise it refuses.
- `changes`: the first section of `sources/<key>/CHANGELOG.md` as plain text (≤ 2000 chars), omitted without a
  changelog. That section's heading must be `## <manifest version>`.
- Limits: `repo.json` ≤ 512 KB, ≤ 500 sources; each manifest ≤ 256 KB.

## Packages (.vovo)

A `.vovo` file is a zip that installs one source from a file, without a repository:

```
<key>-<version>.vovo
  source.json   required, at the root (exact bytes of sources/<key>/source.json)
  icon.png      optional, ≤ 256 KB
  README.md     optional (sources/<key>/README.md)
```

- ≤ 1 MB total, ≤ 8 entries, no directories, no `..`, no absolute paths, nothing else.
- Build with `python3 scripts/pack.py` (all sources) or `python3 scripts/pack.py <key> ...`; the files land in
  `dist/`. Packages are deterministic (fixed timestamps and permissions) and checked against the limits.
- `dist/` is git-ignored: attach the packages to a GitHub release instead of committing them.
- A package has no update channel: importing a newer `.vovo` with the same key updates the plugin; an older
  version is refused ("A newer version is already installed.").

## Versioning and updates

- `version` is semver `MAJOR.MINOR.PATCH` (the v1 schema accepts no prerelease suffix).
- **Bump the version on every manifest change**, even a small one: the app only offers an update when the
  version in `repo.json` is greater than the installed one. PATCH for fixes, MINOR for new features or settings,
  MAJOR when existing settings or behaviour change incompatibly.
- With each bump:
  1. add a `## <new version>` section at the top of `sources/<key>/CHANGELOG.md` (it becomes `changes`);
  2. run `python3 scripts/build-index.py` and commit `repo.json` with the manifest;
  3. run `scripts/check.sh`.
- `scripts/check-versions.py` compares each manifest with the previous commit (`HEAD`; set `VOVO_BASE_REF`, for
  example `VOVO_BASE_REF=origin/v1`, to compare with a branch in CI or before a pull request): a manifest whose
  bytes changed must have a strictly greater version. A new source only needs a valid version.
- The app checks for updates on pull-to-refresh of the Sources screen, when opening it, and at app start after
  12 h. Before applying an update it verifies the manifest as for an install. **If the new version connects to
  hosts the installed one did not, the user must confirm** ("This version also connects to: …"), so add hosts
  only when needed. Setting values are kept; new required settings must be filled before the source is usable.
- Official sources are updated by admins on the server, independently of this repository.

## Adding this repository in the app

In the app: Sources → **+ Add** → paste

```
https://github.com/djabiridrissou/vovo-plugin
```

The app resolves a GitHub repository link to
`https://raw.githubusercontent.com/djabiridrissou/vovo-plugin/HEAD/repo.json` (the default branch), saves the
repository and lists its sources with Install / Installed / Update. A link to a single manifest
(`https://github.com/djabiridrissou/vovo-plugin/blob/v1/sources/gutenberg/source.json`) or a `.vovo` file from a
release also works, for one source.

## Third-party repositories

**vovoscan does not review third-party repositories or sources.** Anyone can host their own `repo.json` with the
same format (on GitHub or any https server) and share its link; users add it at their own risk, and the app
warns them before installing: "vovoscan doesn't review third-party sources. You're responsible for what you read
with them." The Python scripts here can be reused as they are (`build-index.py`, `pack.py`, `check-versions.py`,
`repo_lib.py`): change `REPO_ID`, `REPO_NAME` and `REPO_HOMEPAGE` in `scripts/repo_lib.py`, and keep a stable `id`.
